# Future Edition — Product Reset

**Status:** CURRENT PRODUCT AUTHORITY  
**Date:** 2026-09-21  
**Scope:** public product direction, FE-06R execution order, media validation and progression toward FE-07.

## Why this reset exists

The FE-01 → FE-06 foundations produced useful technical assets, but the first FE-06R public prototype exposed the internal evidence machinery instead of translating it into an exceptional media experience.

The visible prototype is therefore **rejected as a product direction**.

This is not a rejection of the Future Graph, Evidence Engine, Change Engine, provenance model, temporal model or agent-native contracts.

## Authority rule

When documents conflict on the public product, use this order:

1. `CONSTITUTION.md`
2. `VISION.md`
3. this document
4. `MEDIA-PRODUCT.md`
5. `FE06R-GATE.md`
6. `INFORMATION-ARCHITECTURE.md`
7. `DESIGN-SYSTEM-VISION.md`

Historical FE-06R benchmark outputs remain evidence of what was tested at the time, but they are **not proof that the current public product is acceptable**.

## What is preserved

Keep and extend:

- stable IDs;
- Question / Technology / Milestone / Event / Claim / Evidence / Source model;
- Evidence Engine;
- Future Graph;
- Change Engine;
- state resolution;
- provenance and locators;
- temporal semantics and `as_of`;
- correction / retraction / supersession history;
- agent abstention;
- citation atoms;
- Agent Answer Packet;
- delta feed;
- FE-03 / FE-04 / FE-05 scientific tests;
- 10 launch questions and 50 historical baseline events.

## What is rejected

The following are not product authority and must not be cosmetically patched into the next version:

- current FE-06R Home composition;
- current Article composition;
- current Observatory composition;
- technical vocabulary as primary editorial UI;
- named visual primitives imposed before user value is demonstrated;
- automated MEDIA points as proof of product quality;
- responsive/no-overflow PASS as evidence that a page is good;
- a single historical fusion story as substitute for a living media front page.

## Non-negotiable public-product rule

**Human media first → intelligence inside → evidence on demand → machine layer underneath.**

A normal reader must first encounter an excellent media product.

The infrastructure becomes visible progressively when it adds value.

## Required order from now on

### R0 — Authority reset
This document and the v2 product documents are committed.

### R1 — First real canonical Change
Before the new media surface can be accepted, Future Edition must execute at least one real end-to-end knowledge transition:

```
new real-world source
→ resolution
→ claim/evidence
→ previous state
→ human review
→ canonical Change
→ new state
→ human representation
→ machine representation
```

Synthetic lifecycle cases do not satisfy this requirement.

### R2 — Living editorial slice
Use enough of the future FE-07 detection pipeline to surface several genuinely recent candidate changes. Do not open FE-07 as a completed stage; this is a vertical-slice dependency inside FE-06R.

### R3 — Human vertical slice V2
Build only:

`Home → Article → Observatory → Evidence → Original Source`

plus the machine representation of the same canonical object.

Do not generalize to the rest of the site before this slice passes.

### R4 — Capability gate
Apply `FE06R-GATE.md` v2.

If the visible product still needs an explanation to be understood, the gate fails.

### R5 — Scale
Only after the vertical slice passes:
- generalize components;
- expand editorial intelligence;
- open full FE-07;
- continue FE-08+.

## The critical missing proof

At the time of this reset the repository contains historical events, claims, evidence and sources, but no production canonical assessments, reviews or changes in their ledgers.

Therefore the immediate product risk is not only visual design. It is proving that Future Edition can maintain **living knowledge state**.

## Prohibited shortcuts

Do not:

- reuse the rejected Home as the structural base of V2;
- rename internal primitives and claim a redesign;
- fill a current feed with historical baseline content;
- invent scientific state to make the product look populated;
- promote a stage because its CI checks are green;
- use synthetic change scenarios as a substitute for the first real Change;
- expose internal IDs as a requirement for ordinary navigation;
- open FE-07 fully before the V2 vertical slice demonstrates the product.

## Exit condition

This reset stops governing execution only when FE-06R v2 is proved and the repo records a new explicit authority version.
